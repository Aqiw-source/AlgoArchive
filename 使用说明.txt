算法档案 · AlgoArchive 2.5.0

本地版右上角可打开离线使用手册。编辑题目可标记「未做／待补／已通过」、填写错因、关联多个算法；首页可按比赛查看待补清单。全部题目的批量导入先预览，已有题目默认跳过。五个平台标题旁可打开或复制官网链接。

算法和比赛模块分别按蓝、青、绿、琥珀、玫红、紫六色循环分配。
每次新建时确定颜色，改名、分类、筛选、拖动、刷新或重启不改变已分配颜色。
已有模块自动补齐配色，完整备份同时保留颜色和轮换进度。
作者：Aqiw

一、安装与启动

安装版：运行 AlgoArchive-2.5.0-Windows-x64-Setup.exe。安装程序可选择是否创建
桌面快捷方式，默认不勾选。仅当选择“仅为我安装”且当前账户没有配置时，向导才显示数据目录
页，并会把选择的目录写入配置。

为所有用户安装时会跳过数据目录页，每个 Windows 账户首次启动时使用自己的
默认目录；已有 %USERPROFILE%\AlgoArchive\config.json 时安装器不会覆盖配置。
需要更换目录时，请启动程序并在“设置 → 数据管理”迁移。

请下载 AlgoArchive-2.5.0-Windows-x64.zip，不要下载 GitHub 自动生成的
Source code (zip)。源码包不含 Python 运行环境，不能直接双击启动。

便携版：完整解压 ZIP 后双击 AlgoArchive.exe。普通启动不会创建或恢复快捷方式；
需要时打开“设置 → 关于与诊断 → 快捷方式”，点击“创建快捷方式”，或在程序目录运行
.\AlgoArchive.exe --create-shortcut。不要把 AlgoArchive.exe、start.bat、runtime
和 web 分开移动。Windows 不允许便携程序可靠地自动固定“开始屏幕”，固定磁贴
需要在系统中手动完成。

安装版和便携版都包含 自检.bat。需要检查程序完整性时双击运行；自检只使用
独立临时目录，不读取或修改用户数据。C++ 编译器未安装时仍可通过题库自检，
但代码试跑需要在设置中选择 g++。

程序只监听本机地址，默认打开 http://127.0.0.1:8765。端口占用时会选择后续
可用端口，并以启动窗口、设置页和实际打开的地址为准。

使用期间请保留启动窗口。关闭窗口、按 Ctrl+C，或在“设置 → 关于与诊断”
点击“退出算法档案”都可以停止服务。关闭普通浏览器标签页不会结束本地服务。

如果页面显示无法连接，请确认启动窗口仍在运行。需要时，在完整安装目录双击
AlgoArchive.exe，或在该目录打开 PowerShell 并运行 .\start.bat；保留启动窗口，
使用窗口中显示的实际地址。不要双击 web\index.html 启动应用：手册文件可离线
阅读，应用页面需要本地服务。

二、数据和配置

平台填写与侧栏插画：
- 题目和比赛的所属平台可搜索、点击选择十个内置图标平台，也可手动输入。
  力扣、POJ 等扩展平台不会增加侧栏工作空间或首页统计。
- 侧栏左右箭头手动切换调试报错、优化思路、通过庆祝三张内置图，不自动播放。
- 设置中的“侧栏插画”可选择、隐藏或恢复默认庆祝图，不提供自定义插画上传。
  本地重启后保留选择和隐藏状态，完整备份也包含这些设置。
  在线演示仅在当前页面生效，刷新重置，不影响本地题库。

数据目录优先级：
1. 本次明确指定 --data-dir。
2. 当前用户配置文件保存的数据目录。
3. 默认 %USERPROFILE%\AlgoArchive\data。

用户配置默认位于：
%USERPROFILE%\AlgoArchive\config.json

2.1.0 起兼容旧安装器写出的 Windows ANSI/GB18030 配置；新安装器使用 UTF-8
无 BOM。中文用户名路径不会再导致配置解析失败。

程序目录与数据目录相互独立。默认数据目录包含：
- archive.sqlite3：比赛、题目、测试用例、算法、个人资料和业务设置。
- codes：题目代码和算法模板代码。
- avatar：头像图片。
- runtime.lock：单实例锁和实际端口。

“设置 → 数据管理”显示当前生效目录，可以复制路径、打开文件夹或迁移到新的
完整数据目录。迁移前会检查目标状态并创建当前数据备份；迁移成功后需要重新
打开程序。

如果检测到两份可用旧数据，程序不会自动合并或覆盖，而会要求明确选择。
数据库版本过高、数据库损坏或关联代码缺失时，程序会拒绝写入并保留原数据。

三、浏览器

“设置 → 启动与浏览器”可以选择：
- Windows 默认浏览器。
- Microsoft Edge。
- Google Chrome。
- Mozilla Firefox。
- 自定义本机浏览器可执行文件路径。

窗口模式可选普通标签页或应用窗口。应用窗口仅对 Chrome / Edge 提供；其他
浏览器会说明并回退到普通标签页。程序不修改 Windows 全局默认浏览器。

“测试打开”会使用当前填写但尚未保存的设置。浏览器无法启动时会尝试系统
默认浏览器；仍失败时，请复制设置页显示的实际本地地址后手动打开。

四、题库使用

- 首页显示比赛、题目、算法以及 Codeforces、AtCoder、AcWing、洛谷、牛客的平台数量。
- 侧栏提供 Codeforces、AtCoder、AcWing、洛谷和牛客工作空间，可集中查看该平台的比赛和题目。
- 完整比赛可自由填写平台，支持 Codeforces、AtCoder、AcWing、洛谷、牛客等。
- 全部题目统一搜索和筛选，比赛与题目共享同一份记录和代码。
- 算法模板下可关联多道题目、保存多份代码和多个参考链接。
- 全部题目、算法详情、算法卡片和比赛卡片支持鼠标拖动排序；全部题目支持一键逆序。
- 题目名称打开原题；有效链接可在“编辑 / 原题”旁复制；点击题目行空白区域只读预览代码。
- JSON 导入单次最多 200 道题。预览后可逐条决定新增、跳过或更新；已有题默认跳过。只更新资料会保留现有源码和用例。无效行或匹配冲突只能跳过，确认后的变更一起保存，更新已有题前自动创建完整备份。

代码编辑支持 Ctrl+S 保存、Tab 缩进、回车自动缩进和复制代码。C++ 保存为
.cpp，Python 为 .py，Java 为 .java，其他语言为 .txt。单份代码上限 2 MiB。

侧栏“全部题目”下方的“代码试跑”提供独立 C++ 草稿工作区。点击“保存草稿”
或 Ctrl+S 后，代码、测试用例和单例时限保存在当前浏览器的本地存储中；刷新
页面后仍可恢复。它不会创建题目、不会写入 archive.sqlite3，也不会进入题库
备份或迁移。

编译器与运行环境说明

安装版与便携版都附带运行应用所需的 Python；Git 源码、应用 ZIP 和安装程序
均不含 g++ 本体。只整理题库不必下载 C++ 工具链。开发者构建原生启动器时，
发布流水线使用经过摘要核对的 MinGW-w64 静态链接 GCC/C++ 运行库，普通用户
启动应用无需安装这些编译器 DLL。要编译自己的 C++ 程序时才需选用本机 g++。

首次配置编译器：从项目 GitHub v2.4.0 Release 页面下载附件
MinGW-w64-GCC-8.1.0-Windows-x64-posix-seh-rt_v6-rev0.zip。PowerShell 中运行
Get-FileHash "<下载文件完整路径>" -Algorithm SHA256，确认输出与下列值一致：
81a7de2010a66fa1a17b328bc9b8d7534596fe294d078d2cf4b6b706b083af97
摘要不一致时重新下载。右键 ZIP 并选择“全部提取”，解压到固定目录，在目录中
找到 mingw64\bin\g++.exe。打开“设置 → 编译与运行”，填写此 g++.exe 的
完整路径并保存，然后点“编译能力检查”，等待能力检查通过。

编译器查找优先级：先使用设置中填写的路径；路径留空时才查系统 PATH。已填写
路径但文件无效时会报不可用，不会自动改用 PATH 的另一套 g++。可选标准为
gnu++11、gnu++14、gnu++17、gnu++20、c++17 和 c++20；是否受支持取决于所选
g++ 版本，默认使用 gnu++14。

编译阶段最多运行 20 秒；编译通过后，每个用例另按“单例时限”运行，默认
3000 毫秒，可设 50–30000 毫秒。运行全部时，此时限分别应用于每个用例，
不会延长编译时限。Windows 下程序只为编译器及测试子进程临时把所选工具链的
bin 目录加到其 PATH 前面以查找 DLL，不修改 Windows 系统或用户 PATH。

自检.bat 会检查发布文件、运行环境和临时数据库；C++ 项只检查是否找到编译器，
不实际编译。没装 g++ 时自检仍可通过，需另外运行编译能力检查及加法用例。

g++.exe 的完整路径可包含空格或中文，但不要只复制单个 exe。若报缺少 DLL、
cc1plus 或库文件，请重新完整解压并保留 bin、lib、libexec 相对目录。多套 MinGW
并存时，以 AlgoArchive 显示的实际路径和版本为准；VS Code 可能使用不同编译器或
标准。移动工具链后，在设置中更新路径。编译超时（20 秒）、主动停止、单个用例
超时和运行时错误分别代表不同状态；编译成功但答案错误时请比较预期输出和实际
输出（包括空格、换行）。本地用例通过仅代表所测数据通过，不等于在线评测 Accepted。

在线演示是静态示例，不能调用本机编译器。
之后打开“代码试跑”，运行两数相加：输入 2 3，期望输出 5；再加一组输入
-2 2、期望输出 0，并运行全部用例。两组均通过，表示编译器、读入、运行和结果
比较都已验证。详细步骤与常见错误排查见 web\guide\test.html。

五、CPH 兼容测试

题目编辑页下方的“测试用例”面板支持多组输入和期望输出，可以运行当前用例
或全部用例、停止运行，并导入或导出 CPH `.prob` 文件。测试用例保存在
archive.sqlite3，重启、备份和恢复后仍会保留。

程序优先调用“设置 → 编译与运行”中填写的 g++；留空时从系统 PATH 中查找。
未找到时会提示选择完整 MinGW-w64 工具链中的 bin\g++.exe。
Windows 试跑会为子进程补充所选工具链的 DLL 搜索路径，不修改系统 PATH。

默认标准为 GNU++14。可在“设置 → 编译与运行”检查 __int128、multiset 和
unordered_map 的真实编译运行能力，也可以改用其他 g++ 路径和标准。

测试代码只写入系统临时目录，编译成功后逐个用例运行，结束后清理。不会自动
保存代码或提交到在线评测。Windows 系统错误弹窗已对测试子进程禁用。

键盘快捷键（如 Ctrl+S、Tab）只操作当前界面；Windows 启动快捷方式是桌面或
开始菜单中的 .lnk 文件。它们不是同一种快捷方式。手册“快捷方式”章节解释两者。

六、备份与恢复

“设置 → 数据管理”可以创建完整 ZIP 备份、导入其他电脑的 ZIP、恢复列表中的
备份。备份包含 SQLite 数据库、全部代码、头像和业务设置。

恢复前会验证 ZIP 路径、清单、数据库版本和关联代码，并先备份当前数据。
恢复失败会保留或回滚当前数据。应用内最多保留最近 20 份备份。

配置文件中的浏览器绝对路径不写入备份，避免跨电脑恢复时强制使用旧机器路径。

七、日志与诊断

日志默认位于：
%USERPROFILE%\AlgoArchive\logs\algoarchive.log

日志轮转大小约 1 MiB，保留 3 个旧文件。日志仅显示启动、写操作、错误和异常，
隐藏成功静态资源与状态轮询；不记录题目源码、数据库内容或完整请求体。

“设置 → 关于与诊断”显示版本、实际服务地址、数据目录、配置文件、数据库版本
和日志路径，并可打开日志目录。

八、卸载和移动

安装版升级会复用既有安装位置并保留用户数据和配置。卸载默认不删除数据目录、
备份和配置。

便携版整体移动目录后，桌面和开始菜单快捷方式可能失效；请在新的完整目录中
通过设置页或 AlgoArchive.exe --create-shortcut 重新创建。数据目录不受程序
目录移动影响。

九、开发与发布

运行测试：
python -X utf8 -m unittest discover -s tests -v
node --check web/app.js

构建便携 ZIP 和安装程序：
.\scripts\build-release.ps1 -Version 2.5.0

构建产物位于 dist，并生成 SHA-256 校验文件。发布包检查不会包含真实数据库、
用户代码、头像、runtime.lock、旧快捷方式、tests、缓存或备份。
