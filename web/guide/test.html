配置编译器与运行用例

从找到 g++.exe，到亲手跑通第一组输入输出。

找到真正用于编译的 g++.exe

已经用 VS Code 写 C++？可以和 AlgoArchive 共用一套 MinGW。打开 PowerShell，输入 where.exe g++ 查看系统 PATH 里有哪些编译器。出现多个路径时，选与你的 VS Code 构建任务一致的那个；没有输出只表示它不在 PATH 中。

还没有编译器时，可从项目 GitHub Release 下载单独的 MinGW-w64 压缩包。完整解压后找到 mingw64\bin\g++.exe。例如解压在 D:\Tools 下时，实际路径可能是 D:\Tools\mingw64\bin\g++.exe；以资源管理器里的位置为准。

在设置里保存并验证

  1. 点左下角「设置」，进入编译器设置，找到「C++ 编译与运行」。已显示「可用」时，可点「复制实际路径」，确认是不是你想用的版本。
  2. 在「g++ 可执行文件路径」中填入完整文件路径，不要填 ZIP、文件夹或一条编译命令。要使用 PATH 中的 g++，把路径框留空。
  3. 初次配置可保留默认的 gnu++14。点「保存编译器设置」，检查实际路径和版本，然后点「编译能力检查」看结果。

用一组小数据验证整个流程

打开左侧「代码试跑」并输入下面的程序。试跑草稿独立于题库，不必为了检查配置创建一道新题。

#include <iostream>
int main() {
    int a, b;
    std::cin >> a >> b;
    std::cout << a + b << '\n';
}
  1. 第一组输入填 2 3，期望输出填 5，运行当前用例。查看实际输出是否为 5。
  2. 再添加一组：输入 -2 2，期望输出 0，运行全部。两组均通过，就验证了编译、读入、运行和输出比较。
  3. 在正式题目的编辑页，点「保存用例」可供下次复测；已有的 CPH 用例可从 .prob 文件导入。

按现象排查

显示「未找到 C++ 编译器」
核对填的是 g++.exe 文件本身。优先填写绝对路径；如果刚修改过系统 PATH，请重启本地程序再检查。
能找到 g++，但编译提示缺少程序或 DLL
不要单独复制 g++.exe。重新完整解压工具链，保留 bin、lib、libexec 等目录的相对位置，再运行能力检查。
能编译，但用例不通过
先读实际输出。如果题目只要一个数字，请去掉「请输入」之类的提示语，再检查换行、输入顺序和算法结果。
在在线演示里找不到本机编译器
演示页可以读写示例代码，不能调用你电脑上的 g++。请在 Windows 本地版执行本章步骤。
